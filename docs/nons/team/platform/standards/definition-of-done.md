# تعریف انجام شده
**Definition Of Done (DoD)**

نسخه 1.0 | معیار پذیرش برای همه Features، Services و Pull Requests

---

## اصل کلی

هیچ قابلیت، سرویس یا Pull Requestای کامل محسوب نمی‌شود مگر اینکه **همه** شرایط زیر را داشته باشد.

---

## 1. چک‌لیست اصلی

### کد (Code)

- [ ] پیاده‌سازی کامل انجام شده است
- [ ] کد از قراردادهای نام‌گذاری پیروی می‌کند
- [ ] کد از قوانین زبانی (انگلیسی) پیروی می‌کند
- [ ] هیچ `console.log` یا عبارت Debug باقی نمانده است
- [ ] هیچ راز یا اعتباری در کد نیست
- [ ] خطاها به درستی مدیریت شده‌اند (بدون try/catch خالی)
- [ ] کد توسط حداقل یک نفر دیگر Review شده است

### تست (Testing)

- [ ] تست‌های واحد (Unit) برای منطق بحرانی نوشته شده است
- [ ] تست‌های یکپارچه (Integration) برای مسیر خوشحال و خطاها نوشته شده است
- [ ] همه تست‌ها به صورت محلی قبول می‌شوند
- [ ] تست‌ها در CI سبز هستند

### مستندات (Documentation)

- [ ] `docs/README.md` به‌روزرسانی شده است (در صورت تغییر رفتار)
- [ ] `docs/openapi.yaml` به‌روزرسانی شده است (در صورت تغییر API)
- [ ] `docs/events.md` به‌روزرسانی شده است (در صورت تغییر رویدادها)
- [ ] `docs/database.md` به‌روزرسانی شده است (در صورت تغییر دیتابیس)

### دمو (Demo)

- [ ] `demo/index.html` به‌روزرسانی شده است (در صورت تغییر رفتار قابل مشاهده)
- [ ] دمو در مرورگر به درستی کار می‌کند

### تغییرات (Changelog)

- [ ] `CHANGELOG.md` به‌روزرسانی شده است
- [ ] مدخل در بخش `[نسخه منتشر نشده]` ثبت شده است

### پیکربندی (Configuration)

- [ ] `.env.example` به‌روزرسانی شده است (در صورت اضافه شدن متغیر جدید)
- [ ] متغیرهای محیطی جدید مستند شده‌اند
- [ ] Dockerfile در صورت نیاز به‌روزرسانی شده است

### زیرساخت (Infrastructure)

- [ ] Docker Image ساخته می‌شود
- [ ] سرویس به صورت محلی قابل اجرا است
- [ ] مهاجرت‌های دیتابیس (در صورت وجود) کار می‌کنند

---

## 2. چک‌لیست پیش از انتشار (Pre-release)

- [ ] نسخه سرویس مطابق با Semantic Versioning افزایش یافته است
- [ ] CHANGELOG نهایی شده است (تاریخ به جای `[نسخه منتشر نشده]`)
- [ ] Git Tag ایجاد شده است: `{service}/v{version}`
- [ ] GitHub Release ایجاد شده است
- [ ] مستندات Migration (در صورت MAJOR) آماده است

---

## 3. چک‌لیست Blueprint (فاز طراحی)

قبل از شروع توسعه هر سرویس:

- [ ] `blueprint/blueprint.md` نوشته شده است
- [ ] `blueprint/requirements.md` نوشته شده است
- [ ] `blueprint/scenarios.md` نوشته شده است
- [ ] API اولیه مشخص شده است
- [ ] رویدادهای اولیه مشخص شده است
- [ ] مدل داده اولیه طراحی شده است
- [ ] حداقل یک نسخه از `demo/` (HTML/CSS) ساخته شده است
- [ ] Blueprint توسط تیم تأیید شده است

---

## 4. مصادیق رد (وقتی DoD قبول نیست)

| سناریو | وضعیت |
|---|---|
| کد کار می‌کند اما تست ندارد | ❌ رد |
| تست‌ها سبز هستند اما CHANGELOG به‌روز نشده | ❌ رد |
| مستندات آپدیت شده اما دمو تغییر نکرده | ❌ رد (در صورت تغییر UI) |
| همه چیز کامل است اما `.env.example` قدیمی است | ❌ رد |
| کد انگلیسی است اما کامنت فارسی دارد | ❌ رد |
| Blueprint تأیید نشده اما توسعه شروع شده | ❌ نقض فرآیند |
