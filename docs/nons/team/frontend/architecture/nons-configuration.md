# لایه پیکربندی پلتفرم (Nons Configuration Layer)

پوشه `.nons/` در دایرکتوری ریشه پروژه، مالک و مرجع انحصاری تمام تنظیمات، تم‌ها، منوها و اطلاعات ساختاری پلتفرم Nons است. این لایه به صورت فایل‌های YAML پیکربندی می‌شود تا از پیچیدگی‌های کدنویسی دور بوده و به راحتی توسط ابزارهای خودکار یا برنامه‌نویسان قابل ویرایش باشد.

---

## ساختار دایرکتوری `.nons/`

```
.nons/
├── config.yaml          # تنظیمات اصلی پروژه و مشخصات کلی پلتفرم
├── theme.yaml           # پوسته‌ها، پالت رنگ‌ها و نگاشت توکن‌های گرافیکی
├── locale.yaml          # تنظیمات زبان و ترجمه‌های متون ثابت
├── navigation.yaml      # منوها، سایدبارها و پیوند آن‌ها با دسترسی‌ها
├── permissions.yaml     # تعاریف و قراردادهای دسترسی کاربری
├── services/            # رجیستری سرویس‌های بک‌اند (تولیدشده توسط nons service add)
│   ├── auth.json
│   └── iam.json
├── registry/           # Service Manifestها (تولیدشده توسط nons registry build)
│   ├── auth.json
│   └── iam.json
└── generated/           # مصنوعات تولیدشده (تولیدشده توسط nons generate)
    ├── types/
    ├── api-client/
    └── hooks/
```

## تشریح وظایف فایل‌های پیکربندی

### ۱. فایل `config.yaml`
این فایل مسئولیت نگهداری تنظیمات اساسی و کلان پروژه را بر عهده دارد.
* **شامل:**
  * مشخصات کلی و شناسه‌های پروژه (مانند نام، آیکون و دامنه).
  * تنظیمات عمومی و متغیرهای اصلی پلتفرم Nons.
  * فعال یا غیرفعال بودن قابلیت‌ها و زیرسیستم‌ها (مانند سیستم اودیت‌لاگ، چت یا گزارش‌گیری).

### ۲. فایل `theme.yaml`
این فایل مسئول یکپارچه‌سازی ظاهر برنامه و از بین بردن هرگونه استایل‌های هاردکد شده (Hardcoded Styles) در کامپوننت‌ها است.
* **شامل:**
  * تعریف پالت‌های رنگی تم‌های روشن و تاریک.
  * نگاشت توکن‌های سیستم طراحی (`Token Mapping`) نظیر فاصله‌ها، گوشه‌ها (`Border-Radius`) و فونت‌ها.
  * پیکربندی سیستم ظاهری پروژه (`Design System Configuration`).

### ۳. فایل `locale.yaml`
مدیریت زبان‌ها و ترجمه متون برای چندزبانگی فرانت‌بند از طریق این فایل انجام می‌شود.
* **شامل:**
  * تعیین زبان پیش‌فرض سیستم (مثلاً `fa` یا `en`).
  * ترجمه تمام متون استاتیک و عمومی مورد استفاده در پنل‌ها (مانند دکمه‌ها، عنوانین صفحات، پیغام‌های موفقیت و خطا).

### ۴. فایل `navigation.yaml`
منوها و نوار ابزارهای ناوبری به صورت ساختاریافته در این فایل تعریف می‌شوند.
* **شامل:**
  * تعریف درخت منوها (منوی کناری، هدر، منوی کاربری).
  * مشخص کردن روت‌ها و مقاصد هر دکمه به صورت داینامیک.
  * برقراری پیوند میان آیتم‌های ناوبری با سیستم سطوح دسترسی آینده.

### ۵. فایل `permissions.yaml`
این فایل وظیفه تعریف قراردادهای امنیتی و سطوح دسترسی بصری را در پلتفرم بر عهده دارد.
* **شامل:**
  * تعریف نقش‌ها (`Roles`) و دسترسی‌ها (`Permissions`) در قالب قراردادهای پلتفرم (`Permission Contracts`).

### ۶. دایرکتوری `registry/`
این دایرکتوری توسط دستور `nons registry build <service>` پر می‌شود و شامل Service Manifestهای JSON است. هر Manifest از روی OpenAPI سرویس بک‌اند تولید شده و شامل:
* فایل‌های Manifest سرویس‌ها (نظیر `auth.json`، `iam.json`)
* عملیات (Operations) با متادیتا (auth, timeout, retry, cache)
* تایپ‌های مورد نیاز و Security Schemeها

### ۷. دایرکتوری `generated/`
این دایرکتوری توسط دستور `nons generate` پر می‌شود و شامل کدهای تایپ‌پذیر مصرف‌کننده API (Types, API Client, Hooks/Composables) است. همه چیز هم‌زمان و متناسب با فریم‌ورک پروژه (React، Vue، Flutter، ...) تولید می‌شود. ویرایش دستی فایل‌های این دایرکتوری ممنوع است.
