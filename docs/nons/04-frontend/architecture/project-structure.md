# ساختار پروژه (Project Structure)

معماری پلتفرم Nons بر اساس یک اصل اساسی بنا شده است: **تفکیک کامل پیکربندی‌های پلتفرم از بدنه کد اجرایی برنامه (Implementation Code)**. بر این اساس، پروژه‌های فرانت‌اند باید به دو بخش مجزا تقسیم شوند: پوشه پیکربندی پلتفرم (`.nons/`) در ریشه پروژه و پوشه پیاده‌سازی بصری و کلاینت (`src/`).

---

## ساختار دایرکتوری درختی ریشه پروژه

پروژه‌های مصرف‌کننده پلتفرم Nons باید دایرکتوری ریشه خود را مطابق الگوی زیر ساختاردهی کنند:

```
project/
├── .nons/              # لایه پیکربندی پلتفرم (خارج از کدهای منبع برنامه)
│   ├── config.yaml
│   ├── theme.yaml
│   ├── locale.yaml
│   ├── navigation.yaml
│   ├── permissions.yaml
│   ├── services/       # رجیستری سرویس‌های بک‌اند (تولیدشده توسط nons service add)
│   │   ├── auth.json
│   │   └── iam.json
│   ├── registry/       # Service Manifestها (تولیدشده توسط nons registry build)
│   └── generated/      # مصنوعات تولیدشده (تولیدشده توسط nons generate)
├── src/                # پیاده‌سازی کدهای اجرایی برنامه
└── package.json        # تنظیمات و وابستگی‌های پروژه
```

---

## ساختار دایرکتوری کدهای برنامه (`src/`)

پوشه `src/` منحصراً مسئول پیاده‌سازی و ساخت ابزارهای اجرای کلاینت و رابط کاربری (Application Implementation) است و به بخش‌های زیر تقسیم می‌شود:

```
src/
├── pages/              # منطق و کنترلرهای صفحات پنل کاربری
├── templates/          # قالب‌ها و ساختار چیدمان بصری کامپوننت‌ها
├── components/         # کامپوننت‌های پایه و ماژول‌های UI Kit غیر وابسته به دامنه
├── layouts/            # لایه‌های عمومی و بدنه کلی صفحات (مانند هدر و سایدبار)
├── providers/          # پرووایدرهای کانتکست و وضعیت سراسری کلاینت
└── hooks/              # هوک‌های سفارشی کلاینت برای استفاده مجدد از منطق‌ها
```

---

## قوانین و محدودیت‌های توسعه (Strict Rules)

1. **قانون ممنوعیت پیکربندی در `src/`:** هیچ‌گونه اطلاعات پیکربندی، منو، تعاریف دسترسی یا مشخصات پلتفرم (Platform Configuration) نباید در داخل پوشه `src/` قرار گیرد. پوشه `src/` صرفاً وظیفه خواندن و اجرای پیکربندی‌ها را از لایه پلتفرم دارد.
2. **پایداری ساختار کد:** معماری `src/` باید به گونه‌ای طراحی شود که در صورت تغییر پیکربندی‌ها در لایه پلتفرم، نیازی به بیلد مجدد یا دستکاری در کدهای داخل `src/` نباشد.
3. **پشتیبانی از فریم‌ورک‌های چندگانه:** اجزای درون پوشه `src/` می‌توانند بر اساس فریم‌ورک مورد استفاده در پروژه (مانند React یا Vue) پیاده‌سازی شوند، اما خروجی و منطق تغذیه آن‌ها همیشه یکسان است.
